# 発射機の統合版・手動操作(integration/)

ノートブック `Untitled-2.ipynb`(モーター・キー操作)と `stattle.ino`(Arduino:ローラーと装填)に、
カメラ(`realtime_detect.py` のシャトル検出と、`realtime_pose_detect.py` の人の検出)を加えて、
1つのプログラムにまとめたもの。

- **手動操作版**。発射機はキー操作だけで動かす。カメラはシャトルと人を検出して表示・記録するが、
  その結果で自動的に狙ったり撃ったりはしない(`launch_control/` の判断は入れていない)。
- コードは `integration/` の中だけで完結している。外のコードは import しない(元のファイルはそのまま残してある)。
  ただし、今後も更新されるデータ(学習済みモデル、キャリブレーション)は、コピーせず元の場所を参照する
  (下の「外から参照するファイル」)。
- 2026-11-13 に、発射機の「実機での確認手順」1〜7 をすべて実機で行い、すべて成功した(結果は末尾の「実機確認の結果」)。
  カメラを加えた後の確認(手順8)も実機で確認済み。

## 準備(Windows)

1. ノートブック(`Untitled-2.ipynb`)のカーネルを止める。
   動いたままだと COM5・COM6 を開いたままになっていて、統合版がポートを開けない。
2. ライブラリを入れる(ノートブックを動かしていた anaconda の環境でも、`venv_win` でもよい)。

   ```powershell
   cd \\wsl.localhost\Ubuntu-22.04\home\kr\atom-badminton-ai   # Ubuntu-22.04 の部分は自分の WSL の名前(wsl -l -v で確認)
   pip install -r integration\requirements.txt
   ```

3. Arduino には `arduino/stattle/stattle.ino` を書き込んでおく(リポジトリ直下のものと同じ中身)。
4. デバイスマネージャーで COM 番号を確認する。`config.py` と違う場合は、起動時の引数で指定する。

## 起動

```powershell
python integration\main.py                       # 実機(CAN: COM6、Arduino: COM5)+カメラ
python integration\main.py --serial-port COM7 --can-channel COM8@115200   # COM 番号を変える
python integration\main.py --no-camera           # カメラを使わない(発射機だけ)
python integration\main.py --camera-file X.mp4   # カメラの代わりに動画ファイルを使う
python integration\main.py --mock                # 偽物のモーターと Arduino(カメラは本物。--no-camera と組み合わせ可)
python integration\main.py --mock --mock-can-fail-after 10   # 10秒後にモーターの通信エラーを起こす(R キーの確認用)
```

- 起動すると、まずカメラを準備する(モデルの読み込みに数秒かかる)。Elgato Facecam 4K を名前で自動選択し、
  見つからずにカメラが複数あるときは、コンソールで番号を選ぶ。
  **カメラが起動できなくても、発射機の操作はそのまま続けられる**(操作画面に理由が出る)。
- 次に Arduino のリセットを2秒待つ。その後、保持ループが始まり、**モーターがすぐに原点(yaw 145°、pitch 165°)へ動き出す**(ノートブックと同じ)。
- ログはコンソールと `integration/logs/launcher_日時.log` に出る(`logs/` は Git の管理外)。

## キー操作

**「Launcher Control」(操作画面)か「Camera」(カメラ映像)のウィンドウが前面にあるときだけ反応する。**
ノートブックの pynput と違い、他のウィンドウで打った文字では発射しない。

| キー | 動作 | 送る内容 |
|---|---|---|
| `1` | 発射(下の条件がそろっているときだけ) | Arduino へ `1\r\n` |
| `2` / `3` / `4` | ローラーの強さ 弱(20%)/中(50%)/強(100%) | Arduino へ `0,1\r\n` / `0,2\r\n` / `0,3\r\n` |
| `5` | ローラー停止 | Arduino へ `0,0\r\n` |
| `W` / `S` | pitch を −2° / +2°(ノートブックと同じく W がマイナス) | 保持ループが送る目標角を変える |
| `A` / `D` | yaw を −2° / +2° | 同上 |
| スペース | 停止:ローラー停止+その場で保持+強さを設定し直すまで発射不可 | `0,0\r\n`、目標角を現在角に置き換える |
| `R` | モーターの通信を再開(通信エラーで止まった後) | CAN を開き直して保持ループを再開 |
| `Q` | 終了 | 終了処理(下記) |

単品のカメラスクリプトにあった Esc での終了はない(Q だけ)。

大文字・小文字のどちらでもよい。可動範囲を超えた分は、範囲の端に丸めて警告を出す。

## 画面の見方

画面は2つ。どちらかのウィンドウを閉じると、プログラム全体が終了する(終了処理は必ず行う)。

**Camera(カメラ映像)**:単品スクリプトと同じ表示。
- シャトル:検出した枠(緑)、採用した枠(赤)、左上に位置 X/Y/Z
- 人:骨格、立ち位置に使った点(足首か肩。黄)とその中点(赤丸)、その下に立ち位置 X/Z と、どちらを使ったか
- 右上に fps

**Launcher Control(操作画面)**:
- モーターの保持ループが動いているか(止まっていれば理由と「R で再開」)
- yaw・pitch の目標角と現在角(現在角が 0.5 秒以上届いていなければ `---`)
- ローラーの強さ、装填部のシャトル検知の有無(Arduino から 0.2 秒以上届いていなければ「不明」)
- 発射できるか、できない場合はその理由
- 直前の発射を確認できたか(発射後 1 秒以内にシャトル検知が 1→0 になれば「確認できた」)
- カメラの状態(fps、止まっていればその理由)、映像のシャトルの位置、人の立ち位置、CSV に記録した件数
- 最近のメッセージ(警告は黄、エラーは赤)

## カメラの処理

- フレームごとに YOLO でシャトルを検出し、一番信頼度の高いものの位置を記録する。
- MediaPipe は `POSE_INFERENCE_INTERVAL`(2)フレームに1回だけ推論する。立ち位置は、推論したフレームのうち
  立ち位置を出せたときだけ記録する(単品スクリプトは推論しないフレームでも前回の結果を記録していた)。
- 人の立ち位置(座標はカメラが基準)は、次の順に試して求める。
  1. 両足首がはっきり見えていれば、足首の中点を床に投影する(単品スクリプトと同じ)
  2. 足首を見失ったときは、両肩がはっきり見えていれば、肩の中点が床から `SHOULDER_HEIGHT_CM`(140cm と仮定)の
     高さにあるとして、その高さの水平面に投影する。身長などで1割前後の誤差が出る
- 今のカメラの設置は床から約20cm・約19°上向き(角度は録画から求めた値)。画面の一番下は水平より約6°下を
  見ているので、カメラから約1.1m以上離れた人は足首から出せる。それより近いときや、動いていて足首を見失ったときは肩から出す。
- 人の立ち位置の CSV には、単品スクリプトの5列の後ろに `method`(`ankle` / `shoulder`)を足した。
  `shoulder` の行の u・v は肩の中点。
- CSV は単品スクリプトと同じ場所・ファイル名・列で保存する(`trajectories/shuttle_trajectory_日時.csv`、
  `person_positions/person_position_日時.csv`)。途中で異常終了しても残るよう、1行ずつ追記する。
- カメラの処理は別スレッドで動く。YOLO が重くても、操作画面とキーの反応は遅れない。
  カメラ側でエラーが起きたら、カメラだけが止まる(発射機の操作は続けられる)。

## 発射できる条件

`1` キーを押したとき、次の条件が**すべて**そろっていれば Arduino に `1` を送る。
1つでも欠けていれば送らず、理由を画面に出す。

1. 停止(スペース)の後なら、強さを設定し直していること
2. 強さが 1〜3 であること。0 のときに送らないことで、Arduino の「起動直後の1回だけ強さ0でも発射してしまう」不具合を避けている
3. シャトルを検知していること(最新の値が 1 で、受け取ってから 0.2 秒以内)
4. 強さを変えてから `ROLLER_SPINUP_SEC`(仮に 1.5 秒)たっていること。
   Arduino は、シャトルの検知なしが 10 秒続くとローラーを止め、シャトルが入った瞬間に回し直す。そのため、10 秒以上検知がなかった後にシャトルが入ったときも、そこから待ち直す
5. 前の発射から `FIRE_INTERVAL_SEC`(仮に 2 秒)たっていること
6. モーターの保持ループが動いていること

## 終了処理

Q キー、ウィンドウを閉じる、Ctrl+C、予期しないエラーのどれで終わっても、必ず次を行う。
途中の手順でエラーが起きても、残りの手順は続ける。安全に関わる発射機を先に止める。

1. Arduino に `0,0` を送る(ローラー停止)
2. 保持ループを止め、CAN を shutdown する
3. Arduino のシリアルポートを閉じる
4. カメラを止め、MediaPipe と CSV を閉じる

## ノートブックからの主な変更点

| 項目 | ノートブック | 統合版 |
|---|---|---|
| キー入力 | pynput(パソコン全体のキーに反応する) | OpenCV のウィンドウが前面のときだけ |
| モーター104の呼び方 | ROLL | pitch |
| CAN の送受信 | 保持ループのスレッドと、メインの処理の両方から | CAN スレッド1つだけ |
| 現在角 | 保持ループでは読んでいない | 同じスレッドで、受け取ったフィードバックから更新し続ける |
| 可動範囲のチェック | 6か所(キー操作では丸め、それ以外ではエラー) | CAN に送る直前の1か所。範囲外は丸めて警告を出す |
| 通信エラー | スレッドが止まっても「動作中」の印が残り、再開できない | 画面とログに出す。R キーで再開できる |
| 送信ログ | 送るたびに表示(50ms ごとに2行) | 表示しない(警告とエラーだけ) |
| Arduino からの受信 | 読んでいない | 受信用のスレッドで読み続け、発射の判定と確認に使う |
| 発射 | 条件の確認なし | 上の6つの条件を確認する |
| 終了処理 | `ser.close()` は手動、CAN は閉じない、`0,0` は送らない | 必ず行う |

速度・加速度の送り方(10 で割らない)と、角度・ID・原点・可動範囲・周期の値は、ノートブックと同じにしてある。

## 自動・学習版(auto_main.py)

カメラで見つけた人に向けて、yaw と pitch を自動で合わせる。撃った結果を**ターミナルに文章で入力**すると、
それを記録して狙いの計算を合わせ直す(学習)。手動版(`main.py`)はそのまま残してあり、動きは変わらない。

```powershell
python integration\auto_main.py                  # 実機+カメラ
python integration\auto_main.py --mock --camera-file X.mp4   # 実機なし・動画で確認
python integration\auto_main.py --no-record      # 録画しない
```

### キー(手動版のキーはすべてそのまま使える)

| キー | 動作 |
|---|---|
| `M` | 自動狙い オン/オフ。人に向けて yaw・pitch を合わせ続ける(強さが 0 のときは yaw だけ) |
| `F` | 自動発射 オン/オフ(自動狙いがオンのときだけ)。下の条件がそろったら撃つ |
| `1` | 発射(手動版と同じ。自動版では記録も残る) |
| `W/A/S/D` | 手で向きを変える。**自動狙いは切れる** |
| スペース | 停止。**自動狙い・自動発射とも切れる** |

起動したときは、自動狙い・自動発射ともオフ。

自動発射の条件:自動狙いがオン、人が見えている、人が `AUTO_FIRE_STABLE_SEC`(1.5 秒)ほぼ止まっている、
狙いが合っている(現在角と目標角の差が 1° 以内)、届く距離、前の発射から `AUTO_FIRE_INTERVAL_SEC`(5 秒)たっている、
手動版の発射の条件(シャトルあり、ローラーが回っている など)。そろっていない理由は操作画面に出る。

### 結果の入力(学習)

発射すると、ターミナルに「発射 #12 …。結果をターミナルに入力してください」と出る。**ターミナルをクリックして**
文章を打ち、Enter。直前の発射に付く。左右は**発射機から見て**。

| 入力の例 | 意味 |
|---|---|
| `1m足りない`、`50cm手前`、`あと1.5メートル` | 人の立ち位置より手前に落ちた |
| `2m超えた`、`30cm奥`、`1m飛びすぎ` | 人の立ち位置より奥に落ちた |
| `右に30cm`、`20cm左` | 人の立ち位置より右/左に落ちた |
| `1m足りなくて右に30cm` | まとめて書いてもよい |
| `飛距離4.5m` | 発射口から落ちた位置まで(巻き尺で測ったとき。**人がいなくても使える**) |
| `ちょうど` | 合っていた |
| `#3 1m足りない` | 3番の発射に付ける |
| `取り消し` | 直前の入力を取り消す |
| `help` | 入力の例を出す |

単位が無い数字は、20 未満ならメートル、20 以上ならセンチ。「少し足りない」のように数字が無いものはメモとして残し、学習には使わない。
読み取った内容はログに「#12: 1.00m 手前、右に 30cm → 学習し直しました: …」と出るので、意図どおりか確かめる。

### 狙いの計算と学習の中身

- **yaw** = 発射口から見た人の方向(発射口はカメラの真後ろ 25cm)+ 学習した yaw のずれ。
- **pitch** = シャトルの飛び方の計算(空気抵抗あり、終端速度 6.8m/s、発射口の高さ 135cm)で、
  落ちる位置が人の立ち位置になる角度。同じ距離になる角度は2つあるが、低い方を使う。
- 計算に使う「強さごとの発射の速さ」は、最初は**仮の値**(`INITIAL_LAUNCH_SPEED_MS`。実測なし)。
  結果を入力するたびに、`shots/shots.csv` のすべての記録(強さごとに新しい 30 件)から、
  実際の飛距離に一番合う速さを探し直す。記録の無い強さは、記録のある強さと同じ倍率で動かす。
- yaw のずれは、「発射機が向いていた方向」と「実際に落ちた方向」の差の平均。
- 学習した値は保存しない(毎回 `shots.csv` から計算し直す)。`shots.csv` から行を消せば、その発射は学習に使われない。
- 人の立ち位置(カメラから出す距離)に誤差があっても、「人より何m手前か」で入力していれば、
  その誤差ごと合わせ込まれる(カメラの傾きの誤差などで、距離が実際よりいつも短く出ていても、狙いは合っていく)。

### 記録されるもの(`integration/shots/`、Git の管理外)

| ファイル | 内容 |
|---|---|
| `shots.csv` | 1発ごとに1行。全セッション分を追記。強さ、yaw・pitch(発射した瞬間の現在角)、人の立ち位置、発射口から人までの距離、その時の学習の値、予想した飛距離、録画のファイル名とフレーム番号、入力した結果 |
| `session_<日時>.mp4` | セッションの録画(何も描き込まない映像) |
| `session_<日時>_frames.csv` | 録画の各フレームの時刻(fps が一定でないため) |

### 注意

- 起動直後の計算は仮の値なので、**最初は大きく外れる**前提で、安全な方向・距離で試す。最初は `F`(自動発射)を使わず、
  `M` で狙わせて `1` で撃つのがよい。
- 人の立ち位置は、肩の高さからの推定などで揺れることがある。狙いは 0.6 秒の中央値で合わせているが、
  揺れが大きいと yaw・pitch が動き続ける(モーターは毎秒 3° ほどなのでゆっくり)。
- 1発の入力で学習の値が大きく変わることがある(記録が少ないうちは、1発の結果をそのまま信じるため)。

## 実機での確認手順

**最初はシャトルを入れずに行う。** 装填用モーターはシリアルからは止められない(stattle.ino の仕様)。
いつでも電源を切れるようにし、発射口と可動範囲の近くに人がいない状態で行う。

### 1. 起動と接続の確認

- [ ] ノートブックのカーネルを止めてから `python integration\main.py` を実行する
- [ ] 起動から約 2 秒後に「保持ループを開始しました」と出て、モーターが原点(yaw 145°、pitch 165°)へゆっくり動く
- [ ] 画面に yaw・pitch の現在角が表示され(`---` ではない)、目標角の 0.0° に近づく
- [ ] 「シャトル: 検知なし」と表示される。「不明」なら Arduino の行が届いていない(COM 番号やスケッチを確認)

### 2. 向きと可動範囲

- [ ] `D` を1回押す → yaw の目標角が +2.0° になり、現在角も追いつく。**実際に右と左のどちらへ動いたか**を記録する
- [ ] `W` を1回押す → pitch の目標角が −2.0° になる。**実際に上と下のどちらへ動いたか**を記録する
- [ ] 範囲の端は、少しずつ近づけて、機械がぶつからないか確かめる(yaw ±60°、pitch −50〜+30°)。範囲を超えて押すと警告が出て、端で止まる

### 3. ローラーと発射の判定(シャトルなし)

- [ ] `2` を押す → 画面の強さが 2 になる。**ローラーが回るかどうか**を記録する(推測:Arduino を起動してから 10 秒以上たっていて、シャトルがなければ回らない)
- [ ] `1` を押す → 「シャトルを検知していません」と出て、何も動かない
- [ ] `5` を押す → 強さが 0 になる。もう一度 `1` を押すと「強さが0です」と出る

### 4. 停止(スペース)

- [ ] `2` を押してからスペースを押す → 強さが 0 になり、「停止中です」が理由に出る。モーターがその場で止まる
- [ ] `2` を押すと「停止中」が消える

### 5. 通信エラーと再開

- [ ] 動作中に USB-CAN のケーブルを抜く → 画面が「モーター保持ループ: 停止」(赤)になり、発射できない理由にも出る。
  **このときモーターが位置を保つか、力が抜けるかを記録する**(pitch が重さで落ちる可能性があるので、手を近づけない)
- [ ] ケーブルを挿し直して `R` を押す → 「動作中」に戻る(COM 番号が変わった場合は、いったん終了して `--can-channel` で指定し直す)
- [ ] 動作中に Arduino の USB を抜く → 「Arduino: 受信エラー」と出て、発射できなくなる

### 6. 終了処理

- [ ] `Q`、ウィンドウの×、ターミナルでの Ctrl+C の3通りで終了する。それぞれログに「ローラー停止(0,0)を送りました」「CAN を閉じました」「Arduino のポートを閉じました」が出る
- [ ] 終了した直後にもう一度起動できる(ポートが閉じられている)

### 7. シャトルを入れての発射(1〜6 がすべて問題なかった後)

- [ ] **先に `5` で強さを 0 にしておく**。Arduino は、強さが設定されている状態でシャトルを入れると、その瞬間にローラーを回し始める
- [ ] シャトルを入れる → 「シャトル: 検知あり」になる
- [ ] 安全な方向へ向けてから `2` を押す → 1.5 秒後に「発射: できる」になる
- [ ] `1` を押す → シャトルが出て、画面に「直前の発射: 確認できた」と出る
- [ ] 調整する値を記録する:
  - ローラーが十分に回るまでの時間(`ROLLER_SPINUP_SEC`)
  - 装填用モーターが1回転し終わるまでの時間。これより短い間隔で `1` を送ると、Arduino に無視される(`FIRE_INTERVAL_SEC`)
  - 発射からシャトル検知が 0 になるまでの時間(`FIRE_CONFIRM_SEC`)

### 8. カメラ(カメラを加えた版。実機で確認済み)

- [ ] 起動すると「Camera」と「Launcher Control」の2つのウィンドウが出る。Camera にカメラ映像が映り、右上の fps が極端に低くない
- [ ] シャトルを映すと赤い枠と X/Y/Z が出て、操作画面の「映像のシャトル」にも同じ値が出る
- [ ] 人が映ると骨格が出る。肩が映っていれば、操作画面に「人の立ち位置(肩の高さ 140cm と仮定)」が出る。
  巻き尺で測った距離と比べて、Z がどのくらい合っているかを記録する
- [ ] Camera のウィンドウが前面のときも、W/A/S/D や 1〜5 のキーが効く
- [ ] カメラの USB を抜く → 操作画面に「カメラ: 停止」と出るが、発射機はキーで操作できる
- [ ] カメラを抜いた状態で起動する → 「カメラ: 起動できませんでした」と出るが、発射機はキーで操作できる
- [ ] Q で終了すると、ログに「シャトルの位置を保存しました」「人の立ち位置を保存しました」(検出があった場合)が出て、
  `trajectories/` と `person_positions/` に CSV ができる
- [ ] Camera のウィンドウを × で閉じても、発射機の終了処理(`0,0` の送信など)が行われる

## 実機確認の結果(2026-11-13)

「実機での確認手順」の 1〜7 はすべて成功した(手順8 のカメラも後日確認済み)。記録した結果は次のとおり。

| 項目 | 結果 |
|---|---|
| 向き | D(yaw +)で**右**、W(pitch −)で**上**。つまり yaw はプラスが右、pitch はマイナスが上 |
| pitch の原点 | pitch 0°(モーター 165°)で**水平** |
| CAN が切れたとき | モーターは**位置を保った**(力は抜けない) |
| 速度の単位 | 動く速さは**想定どおり**。10 で割らずに送る今の方式で正しい(ノートブックのコメントの「ERPM/10」が誤り) |
| ローラーの回転待ち 1.5 秒 | 問題なし |
| 発射間隔 2 秒、発射確認 1 秒 | 手順7が成功したので、今の値のまま使う |
| 可動範囲、起動時に原点へ動くこと、再開時の動き、現在角の表示 | 手順1・2・5で問題なし |
